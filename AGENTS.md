# Agent Instructions

This file contains instructions for AI coding agents working on this repository.

## Before Committing Changes

**ALWAYS** run the following checks before creating a commit:

### 1. Generate Documentation

If you modified any chart files (values.yaml, templates, Chart.yaml, or README.md.gotmpl), regenerate the documentation:

```bash
make docs
```

This ensures the README.md files are up-to-date with any changes to values.yaml or templates.

### 2. Lint Charts

Verify all charts pass linting:

```bash
make lint
```

### 3. Validate Templates

Ensure all charts can be templated successfully:

```bash
make template
```

### 4. Run All Checks

To run all checks at once (docs, lint, validate, check, package):

```bash
make all
```

## Important Notes

- **Documentation is auto-generated**: Never manually edit `charts/*/README.md` files. Always edit `charts/*/README.md.gotmpl` templates instead.
- **helm-docs version**: This project uses helm-docs v1.14.2 with `--skip-version-footer` flag. The version footer is disabled in templates.
- **Model names are immutable**: DO NOT change the names of deployed models (mistral-7b-instruct-v0.3, mistral-streaming, mistral-cpu).
- **Example environments**: `deployments/synaplan-standalone/environments/` holds `triton` and `ollama`, one per model backend. Any other environment directory is gitignored. Do not reference non-existent `prod` or `dev` environments.

## CI Pipeline

Every pull request runs the same workflow, including a pull request from one feature branch into another. The required check is **All Checks Passed**. It fails when:

- Documentation generated by helm-docs is out of date
- A chart fails `helm lint`, does not render, or fails kubeconform
- `make check` fails: a helm-unittest suite in `charts/synaplan/tests/` fails, an example does not render to valid manifests, the standalone Helmfile does not render for its `triton` or `ollama` environment, or it accepts an unknown `services.backend`

Run `make all` locally before pushing.
